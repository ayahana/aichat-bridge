# QQ 群聊定制开发计划

基线：上游 mmsx4717/aichat-bridge，提交 81565fa06356d66dcb6c15ff9ab5f70670dc7600。保留 MIT 许可证、作者署名、官方 QQ 收发与网页模型架构、飞书兼容。

## 目标与边界

默认仍仅响应 @；普通群消息仅在已绑定且逐群明确开启后参与。支持明确昵称、引用机器人已确认发出的消息、可选同一发言者短时续聊。没有触发的普通消息绝不自动生成。上下文默认关闭，明确开启后仅保留短时、有条数及字符上限的文字。界面提醒群成员知情与发送 AI 网站的范围。

不更改网关 intent 来假定平台权限，不接入模型 API，不安装扩展或使用真实 QQ / AI 账号。普通事件能否投递和回复须用户在授权环境验证。禁止自动重放网页提问，保留原始 QQ 回复期限、完成归属检查、五槽额度与投递结果不明时的停止保护。

## 实施步骤

1. 建立本计划与独立功能分支，审阅脚本后运行基线检查。
2. 正规化两类群事件，保留可信事件类型、发言者和引用 ID；新增逐群保守策略、短时上下文、冷却、排队限制、暂停及去重/循环保护。
3. 将策略嵌入既有持久队列，身份随任务和提示传递；旧配置无需迁移即可采用安全默认值。
4. 设置页增加群策略编辑与能力观察提示；诊断显示排队、网页接手、提交、生成与回传阶段，缺失信号显示未知，不臆测等待原因。
5. 添加离线单元/集成回归，执行 npm test 与 npm run check，修复问题，写明真实账号验收清单与限制。

## 验收

- 默认仅 @；未配置群普通消息静默；昵称误命中与引用未知 ID 不触发。
- 同人续聊窗口过期/不同发言者不触发；暂停不收新工作；上下文限时、限条、限字符、隔离群，关闭后清除。
- 重复事件、机器人消息、不新鲜事件、突发和队列超限不会制造循环或无界任务。
- 发言者明确，群内文本作为资料而非系统指令；过滤仍覆盖最终提示。
- 原始 deadline、lease、一次提交、发送预算和飞书测试保留。
- 诊断仅记录有限时间、阶段和枚举状态，不记录凭据或新增完整消息日志。
- 真实 QQ 普通事件权限、消息引用字段、被动回复、Edge 睡眠与网页结构由用户后续人工验收，本次不宣称端到端成功。
